# Search Agent

The Search Agent in OmniBrain is responsible for retrieving relevant textual information from the multi-modal vector database. It specializes in semantic search, ensuring that the retrieved content is contextually aligned with the user's query, even if exact keyword matches are not present.

## Role and Responsibilities

The primary function of the Search Agent is to efficiently and accurately retrieve text chunks that are semantically similar to the user's query or an intermediate query generated by the Supervisor Agent. Its key responsibilities include:

1.  **Query Embedding:** The agent takes a natural language query (or a refined query from the Supervisor Agent) and converts it into a high-dimensional vector embedding using a pre-trained embedding model (e.g., OpenAI's `text-embedding-3-small`).
2.  **Vector Database Interaction:** It interacts with the multi-modal vector database (Qdrant or FAISS) to perform similarity searches. The agent queries the database with the embedded query to find the most relevant text chunks based on vector similarity.
3.  **Contextual Retrieval:** Beyond simple keyword matching, the Search Agent focuses on retrieving text that captures the semantic meaning of the query, providing richer and more relevant context for the LLM.
4.  **Filtering and Ranking:** The agent may apply additional filters (e.g., based on document metadata, date ranges) and ranking algorithms to refine the search results and present the most pertinent information.
5.  **Result Formatting:** It formats the retrieved text chunks into a digestible format, often including source document references, to be passed back to the Supervisor Agent for synthesis.

## Implementation Details

The Search Agent is typically implemented as a function or a module that the Supervisor Agent can call. It leverages a Python client for the chosen vector database (Qdrant or FAISS) to perform its operations.

### Key Components:

*   **Embedding Model:** A pre-trained transformer-based model capable of generating high-quality embeddings for text. This model is crucial for enabling semantic search.
*   **Vector Database Client:** An SDK or API client for interacting with Qdrant or FAISS. This client handles connection management, query execution, and result parsing.
*   **Retrieval Logic:** The core logic that orchestrates the embedding generation, vector database query, and post-processing of results.

## Example Workflow

1.  **Supervisor Agent Request:** The Supervisor Agent determines that a user query like "What are the recent market trends affecting the tech industry?" requires textual information.
2.  **Query Embedding:** The Search Agent receives the query and converts it into a vector embedding.
3.  **Vector Search:** The agent sends this embedding to the Qdrant database, requesting the top `k` most similar text chunks.
4.  **Result Retrieval:** Qdrant returns text chunks from various documents that discuss market trends and the tech industry.
5.  **Return to Supervisor:** The Search Agent compiles these text chunks, along with their source metadata, and returns them to the Supervisor Agent for further processing and synthesis into the final answer.
